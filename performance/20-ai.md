# AI for performance analysis

Three levels. Each one gives the model more context and more control.

## 1 · Ask AI in DevTools

Performance panel → right-click an event, or the Insights sidebar → **Ask AI**. Good for "what is
this task?" on one selection. Check your company policy first: the selection is sent to a cloud
model, and enterprise policies can switch the feature off.

## 2 · Trace digest → any model

A saved trace is tens of MB and may contain patient data in strings. Don't paste it. Digest it:

```sh
# Performance → record → ⬇ Save trace
pnpm trace:digest Trace-20261117T101500.json > digest.md
```

`tools/trace-digest.mjs` keeps only numbers: long tasks and their script/layout/paint/GC split,
TBT, short tasks per second, forced reflow candidates, GCs, top self time by function (from the CPU
samples), and the Angular track. About 2 KB. Then prompt with the digest **and** the code it points
at:

```text
This is a performance trace digest of an Angular 22 zoneless app (attached) and the files that
appear in "Top self time" (attached). For each problem: the shape (wall, picket fence, forced
reflow, GC churn), the cause in the code, and the cheapest fix. Rank by impact on TBT. Say what you
would measure to confirm each fix.
```

## 3 · An agent that measures, fixes and measures again

```sh
claude mcp add chrome-devtools npx chrome-devtools-mcp@latest
```

The agent drives Chrome: it opens the page, records a trace (`performance_start_trace`), reads the
insights (`performance_analyze_insight`), reads the code, proposes a fix, and records again.

```text
Open http://localhost:4200/ward?mock&perf=bad and sign in as a nurse. Throttle the CPU 4×.
Record a 10 s trace on the nurse station, then one while opening a bed and going back 5 times.
List every performance problem you can prove from the traces, with the file and line that causes
it. Do not grep for "BAD" and do not read the performance/ folder. For the top 3: apply the fix,
record again, and report the before/after TBT.
```

## The hunt: you vs the agent

Run [the hunt](hunt.md) in pairs while the agent runs the prompt above on the projector. Compare at
the end: which problems did it find, which did it miss, and why?

## Rules

- AI reads traces fast. It doesn't know what your screen must keep doing. You do.
- Give it **numbers and code**, not screenshots and not raw traces.
- Make it prove each fix with a second measurement.
